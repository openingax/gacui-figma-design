# 产品原型 → 草稿：产品和 UI 使用指南

这一阶段不用 Figma 账号、目标文件、节点 ID 或组件映射。当前 agent 理解材料，本地脚本负责保存、检查和生成预览；不额外接入 AI API。

## 可以怎么说

- “这是产品原型，帮我梳理成可预览的草稿，先列出不明确的地方。”
- “给申请表单增加必填申请人，其他页面和字段保持不变。”
- “对比这一版和上一版，说明修改了什么。”
- “把这一版命名为方案A。”“从方案A继续修改，保留中间版本。”
- “确认 v2，导出给我评审。”

截图或文档作为材料交给 agent；能读取哪些格式取决于客户端。遇到无法读取的工程文件，应导出为可读文档/截图，而不是让 agent 猜内容。

## 你会得到什么

- 页面、字段、操作与状态清单，以及来源、判断、待确认事项。
- 本地 HTML 预览，可切换页面、空态、错误态、已填写态等已生成状态。
- 每轮修改的新版本、变化摘要、历史恢复和命名/星标。
- 指定版本的只读 HTML 导出；继续编辑时保留完整草稿目录，不能仅靠 HTML 恢复历史。

未回答的关键问题会显示在预览里，不能被当作已确认；明确确认绑定具体版本和内容摘要。新修改不会自动继承旧版确认。表单成功提交、后台查询等属于静态规则说明，不会真的执行。

## 本轮示例与验证

公开示例是虚构的设备借用管理原型：列表、申请抽屉、空态、已填写和必填错误。第二轮反馈增加申请人，并修改标题和取消规则。没有借用已有业务稿换名字；所有测试数据均明确为演示。

自动测试覆盖：首版未决问题阻止确认、第二轮修改保持列表及旧快照不变、版本差异、模拟确认、指定版导出、防覆盖、从旧版继续。模拟确认只用于测试，不代表任何用户或 UI 已验收。

Figma 完整自动接入单独保留为后续阶段，不会因为草稿已确认而自动开始。当前并未承诺所有组件都能在新 Figma 文件中直接生成完整页面。
