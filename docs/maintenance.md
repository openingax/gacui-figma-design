# 维护、版本和更新

公开版本以本仓库的 PR 为维护入口。UI 设计师可以让 agent：按明确规范来源修改组件规则与实现，列出状态覆盖和前后对照，更新 CHANGELOG 并提交审核。开发 agent 使用同样流程，不能把普通出稿变成修改共享组件。

1. 分支修改，保留行为矩阵。真实设计差异同时体现在实现和说明。
2. 运行 `node scripts/verify.mjs`；涉及 UI 时额外查看真实预览/目标截图。检查通过不替代设计验收。
3. 更新 skill-release.json 的 version/notice 和 CHANGELOG；检查公开文件不包含用户任务、日志、凭据或内部授权映射。
4. 审核后发布不可变 `skill-vX.Y.Z` 标签与 GitHub Release。禁止移动旧标签。
5. 客户端会话开始调用 sync，兼容版本快进，并展示更新摘要后 ack。0.x 的次版本升级保守地要求明确接受；固定版本不会自动升级。

安装入口来自 npx skills，完整运行资源来自本公开仓库。入口协议改变时给出新安装命令；旧协议应拒绝不能识别的运行版本。不要把第三方安装器更新当作运行目录已更新。

回退使用新目录 `sync --version X.Y.Z --workspace <新目录>`，核验任务格式后迁移；不 reset 原任务。公开与内部项目的变更需要逐文件审查，不把私有仓库历史或业务证据整体镜像到这里。自动测试不是 GitHub 强制审核规则，本仓库不声称已配置组织级审批。
