# Gitee 与 GitHub 发行维护

本仓库是独立的 Gitee 公开发行仓库，来源为已审核 GitHub 公开标签。内部开发仓库不参与镜像。首批提供 V1.2.0 和 V1.2.1（最新），组件功能与 GitHub 同名版本一致；以各平台真实标签为准，不把本地文件视为已发布。

## 来源与同步

- GitHub 现有仓库、入口、历史和用户目录保持原样。本仓库的来源、安装及版本检查固定为 `https://gitee.com/xieliying/gacui-figma-design.git`，网络失败不会切换 GitHub。
- 平台常量集中在 Skill 自带的 `scripts/source.mjs`。管理器逻辑共用；不开放任意来源参数给 CLI。
- Gitee 运行目录为 `~/.gacuiagent-gitee/workspace`；已有 GitHub 目录不接管。草稿迁移另行明确操作，不重置旧目录。
- Skill 名仍为 gacui-figma-design：同一 agent 的同一安装路径选择一个平台。不同运行目录不会自动解决入口名称冲突。
- 日志配置仍使用原来的用户级位置，保留用户明确关闭的选择；不迁移或复制凭据。日志/Figma/npm 不是 Git 资源源站，不受此切换影响。
- 同版本共享组件和业务代码应逐文件相同；差异仅为发行来源、文档、发行验证工具及清单。`distribution-manifest.json` 记录上游提交、文件哈希及准确差异清单。
- 按审核后的公开标签构建新目录，审查差异后逐版本提交 Gitee。禁止 mirror、强推、批量复制私有历史、推送未经适配的上游标签。
- 版本号对应上游版本，平台发行提交可以不同。两个平台的发布不是原子事务，各自回读标签和实际安装；失败的一边标未完成，不移动已发布标签。
- Gitee 不会自动执行 `.github/workflows`。首次发布需本机完整验证和真实远程安装，未执行的平台 CI 不得标通过；后续可另行配置 Gitee CI。

## 行为矩阵

| 输入/状态 | 动作 | 结果与副作用 |
|---|---|---|
| Gitee 新入口＋空目录 | sync | 仅从 Gitee 查询标签/克隆；使用独立默认运行目录 |
| Gitee 受管目录 | sync | 仅从 Gitee fetch，安全快进，草稿不变 |
| GitHub 或未知 origin | 管理命令 | 拒绝，不改 remote、不接管目录 |
| 固定版本 | sync | 保持版本并提示可用升级 |
| 本地修改或提交 | sync | 保留现场并阻止升级 |
| 离线 | sync | 已安装版本继续可用；首次安装明确失败 |
| 跨不兼容版本 | sync | 未明确接受则不升级 |
| 软链接/复制安装入口 | status/sync | 自包含，均可找到 source.mjs，无需源码工作区 |
| 显式关闭日志 | sync | 关闭偏好保留，不新增凭据 |

## 验证和发布

运行 `node scripts/verify.mjs`。从真实 Gitee 正式标签使用完整 URL 安装并运行 sync，检查 origin、版本、草稿保存/预览、软链接、固定版本及升级。匿名 Git 验证应关闭凭据助手，记录 Git 资源网络目标，不能仅凭网页公开或 Git 推送成功。

版本回退使用新目录安装已存在的旧 Gitee 标签。首次只有一个标签时，旧版到新版的真实升级不能声称完成；必须有实际历史 Gitee 发行标签后再验证。
